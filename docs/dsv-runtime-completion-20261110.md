# dev20 跨日执行与工作台逐品种启停

日期：2026-11-10，Asia/Shanghai。源码版本 `0.1.0.dev20`。本轮目标是继续补在线运行功能；没有连接账户、读取凭据、执行网络校时或在线报撤单。没有构建/安装新wheel、安装服务、发布或创建提交；独立SDK环境和冻结V7保持不动。

## 已接通的业务行为

### 跨日管理原周期

原单一交易日范围 `KQ_DSV_SIM/1` 继续按原日边界执行。新增 `KQ_DSV_SIM/2`，必须明确列出 `trading_days` 和布尔值 `resume_entries_on_day_change`；保留原账户、账本、profile/calendar哈希、时间窗、风险预算、最大单量与总开仓尝试额度。解析或准备文件不激活交易。本轮只使用测试中的合成范围，没有创建或延长任何实际账户范围。

`DayRecovery` 在原owner/writer中处理换日：先撤销新增权限，接收原单和原生成交，停止旧周期追开余量；旧日活动开仓/平仓余单按原ID撤单，等待原生终态与逐笔明细一致。已确定未发送、部分成交、撤单中、未知发送继续使用原OMS状态，不按超时或日切释放可能量。

原单终态和持仓归属核对一致后，当前源epoch/日历/柜台日的恢复证明才允许原退出继续。SHFE/INE分别创建平今和平昨子单，按DSV使用的固定SDK默认“今昨,开”先今后昨，两个退出子单可以并行，但始终共享原周期的一个剩余目标。DCE/CZCE使用一个组合CLOSE，原生今昨桶与资金报表FIFO成本分别核算。

旧日平今单不会改写成新日平今单。确认原单取消后，新日剩量沿原intent建立新的child/attempt/ordinal，使用新的原生提交日和正确offset；原计划、理论价、保护高点、阶段、收盘引用和已收紧目标保留。过期的原收盘期限继续推动退出，而非绑定到新日收盘重新等待。

带仓重启会重新核对当前原生数据和原在途子单，保留部分成交后的剩量，不重放旧发送。重连后恢复证明须匹配新的源epoch；断线、缺日历/完整同步或UNKNOWN缺原单时保持禁开和待核对。

### 原生历史的两种承接

固定SDK的当前日集合不代表全历史查询。本轮实现两条可核对的承接方式：

1. 原先已通过完整核对并持久保存的原生终态单及其明细，可以在新日当前集合缺少该旧单时作为自有历史证据参与核对。来源事件、水印、摘要及原始明细保持可追溯。
2. 当前原生集合仍能证明原单精确终态时，将此前已持久保存的原生成交回执与当前累计成交量核对，补齐SDK新日集合不再包含的旧日明细。当前日缺少的明细不能用缓存冒充完整同步。

缺失的未决/UNKNOWN原单不适用这两条终态承接；不从本地计划或“查无记录”生成零成交证明。外部持仓、外部原生单或明细冲突不自动认领。SDK未提供的任意历史查询/缺失原单回补渠道仍待补，不将持久回执承接称为新增了远程历史查询接口。

### 次交易日继续运行

新范围只在明确允许的柜台日和时窗内评估新入场，原1.3计划绑定自己的实际入场柜台日。每日报单计数按原生委托时间重新归日，总开仓尝试额度跨日不清零。

只有范围明确开启延续、换日前确实处于武装状态、期间没有操作者暂停/权限改变、原生完整核对通过，才请求次日继续新增。原周期未结清时仍受现有持仓及统一目标门禁约束。暂停、断线后的恢复与进程重启不自动重新武装；存在统计修正屏障也不自动开放新增。

### 工作台逐品种启停

行情页新增“允许该品种新增”状态，以及“启用品种新增”“停用品种新增”按钮。选择一个或多个合约后，通过原 `PAUSE_NEW_ENTRIES` / `ARM_ENTRIES` 的显式CONTRACT范围处理；沿用原Context、账户/boot/revision、payload hash、单writer、正确CommitAck及原回执查询链。原G0协议资源字节不变，ACCOUNT操作语义保留。

停用立即收紧该品种的新增门禁，提交后撤其自有开仓余单；其他品种不因此被全账户暂停，已有保护和退出单不删除。重新启用须在正确Ack后才解除该品种限制，且不为全账户武装。开关独立持久保存并跨重启恢复，不改写profile或旧保护计划。越出当前策略/合约范围的请求拒绝。
