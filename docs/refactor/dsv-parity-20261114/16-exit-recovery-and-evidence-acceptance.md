# 平仓恢复、历史隔离与调度比较验收

适用于 `main` 的 A01、A02、A03、B01 修复，首次验收对应提交 `6468b00`。使用固定版 DSV、合成行情和原生回报、`DEV:` 离线身份、隔离 SQLite 及同用户命名管道。验收保留被测版本、输入和每项实际结果。

## A01 平仓拒发后的同目标恢复

1. 先运行冻结版原策略循环，给两边相同的配置、按轮排序的行情与成交回报。固定样本第 5 轮产生零仓目标，第 6 轮最新价和盘口无效，第 7 轮回到有效报价，第 9 轮完成策略平仓同步。核对原版第 6 轮保留退出，第 7 轮自行重申零仓目标。
2. 在候选的公开 `DsvSession` 上重放相同输入。让隔离端口只对第一笔减仓返回绑定原 effect ID 的 `SendNotAttempted`。检查原子单持久化为 `DEFINITELY_NOT_SENT`，保存原退出目标与持仓。分别重放重复旧报价，以及对手价和最新价均为 NaN、仅有涨跌停边界的报价。两种情况下都应继续等待。
3. 关闭并重开同一账本，补齐原仓位和路由核对，再送入新有效报价。无需追加手工减仓请求。核对目标和修订号相同，新子单使用新身份并关联原拒发子单，只发送剩余所需数量。注入平仓回报后核对逐笔和结清轨迹。
4. 对同一输入另跑一次 SDK 调用异常。原子单保持 `UNKNOWN` 和占用。即使重启、行情恢复并请求同步，原生事实未核齐时也应保持零补报。

原版回放证明退出意图如何跨无效报价续行。候选的本地拒发证明和 `UNKNOWN` 分支由隔离端口分别验证。保留原版输出、候选回执、原子单与后继身份，以及每轮报单计数。[冻结样本与候选复测](../../../output/validation/20261115-review-fixes-independent/test-report.md)

## A02 历史读取期间执行器仍能推进

1. 给隔离事实库准备长历史。首次验收使用 10,000 条五品种合成轮次。通过工作台实际使用的 `snapshot` 请求并开启 `workbench_evidence`，分别测试第一次读取和关闭、重开同一账本后的第一次读取。
2. 记录 snapshot 返回加载状态的时间、后台转为 `READY` 的时间。核对后台使用独立只读连接，由不同线程分批取数并在读取语句结束后解码。
3. 趁历史仍为 `LOADING`，从实际 Qt 工作台发出启动命令。检查执行器能处理命令、返回原回执并更新策略状态。旧测试只计查询耗时，这里同时记录命令在历史仍加载时的进度。后台完成后核对事件和成交展示。遇到暂时读失败时，确认下一次刷新可恢复。

样本的首次及重开快照约 0.8 毫秒返回加载状态，后台约 2.5 秒就绪。耗时受历史大小、设备和负载影响，验收关注查询与执行是否相互等待。[Windows Qt 截图与测量](../../../output/validation/20261115-review-fixes-independent/qt-large-history/findings.json)

## A03 实际界面可见并保留原委托占用

1. 执行器与 Windows Qt 通过实际命名管道连接。从仓库根启动 `python -m online_trader workbench --offline-pipe <隔离管道>`。在「策略事件」核对正常入场、追价上限、缺资金字段、行情过期、等待同步及止损的中文含义，检查可见时间与合约。
2. 准备一笔已知原生身份的活动委托，在界面选择「撤选中委托」，让隔离端口抛出 `OSError`。核对策略事件出现「撤单结果未知」、时间、合约、委托身份、错误码和异常类型。未核齐委托表仍保留这笔 `UNKNOWN` 及原数量占用。注入的原始异常文本不出现在界面。
3. 相同入口重开旧版隔离事实库，检查已结清逐笔价格、保护线和旧拒发记录仍可查。旧记录缺时间时保持空缺，缺细分理由时保留通用原因和原错误码。

## B01 比较器应拒绝有交易差异的轨迹

| 输入 | 预期 |
| --- | --- |
| 原版目标 `[0, 0]`，候选 `[0]` | 通过。相邻重复零可折叠。 |
| 原版 `[0, 5, 0]`，候选 `[0, 5]` | 失败。最终目标不同。 |
| 候选缺失、乱序或重复轮次 | 失败。两边轮次需按相同顺序且身份唯一。 |
| 候选多一轮且多出 `BUY OPEN` 出站包 | 失败。额外轮次及其动作需保留在差异结果。 |

在项目环境运行比较器负例和源码回放回归。

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_dsv_schedule_comparator tests.test_dsv_refactor_repairs tests.test_dsv_round_replay -v
```

按已有运行命令重跑追价、保护、空批次三个标准调度包，以及带 `--verify-slow-partial` 的慢部分成交包。前三包应逐轮一致。最后一包原始差异只可出现在已批准的第 7、9 轮，专用回归还须验证第 7 轮已成 3 手仍保留 5 手目标，第 9 轮已成 5 手且无额外卖平。[固定样本运行命令](15-strategy-sdk-schedule.md#复现)
