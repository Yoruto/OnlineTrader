# 批次03｜替代运行器持久异常诊断

基线 `426ac0f9ca38dbff8b2dc54f3ed70a245ac8eb38`。独立修复 `_serve` 只保留覆盖式 error_code 的问题。新增日志不是 Journal，不授予开仓、撤单或恢复权限，不修改 SDK轮次/停开/关键存储失败处理。

## 行为

在本次运行输出目录追加 `runtime-diagnostics.jsonl`，记录 SDK_ROUND 和已建立输出目录后的 STARTUP_OR_CLEANUP 捕获点。记录发生时间、异常类型、脱敏调用位置、允许的内部错误码、HMAC指纹及事件ID；不保存原始异常消息、局部变量、账户快照、源码行或绝对路径。通过现有 `exception_record` 取得脱敏结构，再按字段白名单输出。

恢复正常后追加 RECOVERED，不覆盖原失败；只有成功且原生状态同步的轮次才记录恢复。status.json 增加 diagnostics 状态、写入失败计数、最近异常ID和相对日志名。正常无异常不创建空诊断文件。

相同异常按1/2/4/8等累计次数写入，改变异常或恢复时补摘要。默认单文件2MiB、3份备份，单条最多64KiB；长堆栈明确标记 truncated。坏尾行只用换行隔开，不将新JSON拼到坏尾部，不改原事实库。

诊断格式化/文件失败只显示 DEGRADED，原轮次继续按原流程处理。关键存储 `_failed` 先尽力记录，再原样抛出；不会被诊断代码转换为恢复成功。

## 保证边界

这是尽力写入的运行诊断，不是断电安全的交易事实事务，不承诺每条异常都能在磁盘故障中保住。轮转会淘汰最旧诊断；强制结束可能丢未汇总的重复次数或末尾记录。读取方应允许跳过损坏尾行。未建立输出目录之前的预检错误仍由原入口报告；本批不宣称覆盖全部早期启动错误。

本批没有把日志IO移到后台，也没有给出固定时延保证；有界轮转与重复合并减少错误风暴写入量，性能仍需Windows长稳验收。没有改中文业务日志、历史事实投影或报告的完整迁移。
