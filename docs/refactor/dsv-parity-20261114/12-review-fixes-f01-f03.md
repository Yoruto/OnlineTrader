# F01–F03：重构候选复审修复

基线：`aa8bd355d44e67d81509d33682e9451a891edade`，目标分支 `refactor/dsv-parity`。本 PR 仅修复已定位的发送结果分类、到期天数和保护线名义统计，不宣称重构完成，不修改主分支、真实账户、历史数据库、依赖或旧执行链。

## F01：明确未调用 SDK 的拒发，不再伪装成 UNKNOWN

`DsvSdkAdapter.send()` 先验证原 owner、未重放身份和已提交 effect。这个身份校验仍在证据边界之外：已调用过的 effect 或来源不明的异常，不能据本轮没有再次调用 SDK 就降级成未发送。

身份成立后，价格、账户范围、窗口及参数构造在 `insert_order` 之前执行。本地拒发返回绑定 effect ID 的 `SendNotAttempted`。只有这一明确结果、全新的 `SEND_POSSIBLE` 子单、零成交、尚无原生身份同时满足时，控制器才持久化 `DEFINITELY_NOT_SENT` 及 `local_send_rejection`。控制器不把它改写成柜台 REJECTED/CANCELLED/FILLED，不伪造 `terminal_confirmed`、原生订单号或成交量。

真正进入 `insert_order` 后的异常，无论是 OSError 还是与本地拒发同码的 TraderError，均继续为 UNKNOWN。成功返回仍仅为 CALL_RETURNED，不是柜台受理、成交或终态。撤单调用异常继续保留原单及占用。

### 收敛与重试

- `terminal()` 对具备完整本地未发送证据的子单表示“该尝试已收敛”，不是柜台终态。它不再进入等待一个不存在订单的同步集合。
- 开仓本地拒发会停止该目标的剩余增仓；原目标次数、scope 计数和分钟机会不退款。零持仓周期可经现有 `settle()` 正常归档，禁止为了补偿一次拒发而重放旧 effect。
- 减仓本地拒发保留真实持仓、退出目标和原拒发记录。相同目标版本不会自动无限重试。新的明确减仓请求或更紧保护目标提高退出版本后，可经原仓位、数量和价格核验准备新子单；旧子单身份不重用。此处是本地拒发后的有界恢复方式，不是新增日停或全账户授权屏障。
- 明确未发送之后出现同子单的原生事实，是证据矛盾，必须显式报错；不能静默忽略或以该本地证明覆盖真实仓位。
- 写入派发结果失败时，已提交的准备记录仍保留，运行器维持既有失败停止/重启核对边界。不得只凭内存中的未发送判断释放重启后的责任。

`EFFECT_RESULT` 和订单快照增加失败阶段、错误码、脱敏异常 ID/栈/指纹。复用原 `exception_record()`，不记录 SDK 原始异常文本、凭据或局部变量。旧 UNKNOWN 不作批量转换；只有本次调用现场的新证据可产生 DEFINITELY_NOT_SENT。

## F02：到期日零点减完整北京时间

依据 [原版静态证据](../../strategy-dsv-evidence.md)“到期阈值”（`StrategyThread._run` 7939–7944），将适配器的日期差改为：

```text
到期日北京时间 00:00:00 − 当前完整北京时间 → timedelta.days
```

不把系统时区当作北京时间，不截掉当前时间。到期日 2026-11-16、当前 2026-11-10 09:06+08:00 时结果为 5，而非 6。午夜恰好时仍为 6；过午夜一微秒变为 5。原阈值比较和缺失到期字段处理不变，未修改界面到期提示工具的显示口径。

## F03：保护线记名义点数，真实成交保持原样

依据 [原版统计证据](../../strategy-dsv-evidence.md)“统计与停开”中 `_run` 7733–7735、7767–7770，PROTECTED_FLOOR 的名义参考价改为理论保护线，而非跳过保护线的最新价。

例如理论入场 100、止盈距离 50、留利比 0.5：多头保护线 125，报价跳到 120 时名义净亏减少 25；空头保护线 75，报价跳到 80 时同样减少 25。零留利比例仍按原解释回退 0.5。保留原浮点计算顺序，不另加价位对齐或四舍五入规则。

决策保留原 `move`（报价相对理论价），新增 `nominal_reference_price` 和 `nominal_move`；`rollback_exit.price` 使用名义参考价。实际行情、理论入场、累计成交金额和 `native_trades` 均不改写。其他止损、止盈、移动及半仓统计不因此改口径，重复保护报价不重复记账。本 PR 不重算已经持久化的历史错误统计；历史修复需独立、有来源的转换。

## 验证及可复现边界

新增 `tests/test_dsv_refactor_repairs.py`，共 25 个测试方法（其中若干方法参数化多个边界）。普通测试使用真实函数/方法、真实 SQLite Journal 和明确 SDK 替身，不连接网络、不创建交易账户锁。另有 1 项 Windows 用例通过公开 DsvSession 构造、原有回放 fixture、关闭/重开及同步验证整链。

本轮实际执行：CPython 3.13.5 / Linux，24 项通过、1 项 Windows 集成跳过；编译检查通过。由于当前执行环境不能直接取得完整可运行仓库，本地通过隔离加载核验过的源文件方法体、原 Journal/值类型/错误诊断及必要纯函数运行这些断言；**没有验证完整模块导入图、Windows 锁、Qt、安装制品、完整测试套件或真实 SDK**。三个修改源文件的修改前 Git blob SHA 均与远端固定提交一致。

| 场景 | 核查结果 |
| --- | --- |
| 本地窗口/价格拒发 | SDK 调用 0，具备未发送证据，无伪造原生终态 |
| SDK 内同码异常/OSError | SDK 调用 1，UNKNOWN，保留责任及脱敏诊断 |

| 提交失败 | 准备记录仍未解决，不靠内存结果重放 |
| 撤单异常 | 保留原单，不将撤单调用当成交或终态 |
| 减仓本地拒发 | 目标与持仓保留，同版本不循环重发，新审核目标才可生成新子单 |
| 到期午夜/盘中/阈值/时区/过期负天数 | 与冻结表达式一致 |
| 多空保护线恰好/跳过/跳过入场/零比例 | 名义参考线一致，实际价和成交数据不变 |
