## 后续 Runtime 测试入口迁移候选

2026-11-19 后续候选将 Trading Workbench 从“只保存操作草稿”改为在界面内解锁操作员并直接通过 Runtime 控制协议提交。新增 `authenticate` 协议动作，令牌只驻留 Qt 进程，每次命令仍在接口端重新鉴权；提交绑定账号、owner boot 和配置版本，超时只查原命令 ID。

## 实现范围

| 能力 | 当前入口及所有权 |
| --- | --- |
| 独立启动 | `online-trader runtime run --root <目录>`；原执行 owner 登录模拟账户、驱动 SDK、运行原策略、提交原订单并维护保护。 |
| 可移植配置 | 运行目录中的 `runtime.json`、`private/OnlineTrader-defaults.json` 和 `OnlineTrader-parameters.json`；新 Runtime 不使用 Windows 凭据库。 |
| 原账本 | 每账号继续使用原执行 SQLite。首次启动自动建账；没有单独 `runtime.sqlite3`。换机导出配置、原账本一致性副本和清单。 |
| 操作员接口 | CLI、Python 和本机 JSON 协议共用版本化命令。人工与策略开仓权限分开；人工禁开在原策略评估及发送前复核，平仓和保护不因此停用。 |
| 状态读取 | Runtime 主动推送基线或差量；客户端每 2.5 秒按版本和摘要对齐。接口进程可退出和重建，不参与交易 owner 循环。 |
| 账户与历史 | 附着当前 owner 读取资金、持仓、原生委托和逐笔成交；跨日入口按原账本水位稳定分页，区分观察日与自有核证成交日。 |
| 离线复现 | `qa/runtime_replay.py` 使用隔离事实验证原执行规则，不进入正式 wheel，也不连接账户。 |

设计和命令合同见[独立运行时设计](standalone-trading-runtime-20261119.md)，账户数据及 SQLite 选择见[账号数据同步逻辑设计](../account-data-sync-design-20261119.md)。
