# OnlineTrader G0 开发规格入口

规格集：`OT-G0-1`。日期：2026-11-09（Asia/Shanghai）。

**G0 的工程规格与准备清单已形成，可据此拆分 G1 的领域、存储、IPC 和保护解释器开发任务。** 这不表示规则已批准、技术兼容已实测或通道可上线。所有 B01–B20 仍为 PROPOSED；G1 尚未开始编码。

后续实施进展（2026-11-09）：独立工程 `E:\online-trader` 已开始G1并形成首个本地开发原型，当时进度见[历史 G1 状态](../legacy-runtime/g1-status.md)，不合并进V7运行时。本页下文“尚未编码”等描述保留G0结案时的范围；不代表独立工程此后没有实现，也不把其本地检查换算成在线验收。

## 2. 已确定的工程决定

| 决定 | G1实施约束 |
| --- | --- |
| 独立产品 | 目标工程建议E:\online-trader，独立代码/环境/包/数据；不调用V7/DSV运行时，不复制秘密或闭源核心 |
| 单一状态所有者 | 内核串行归并权威事实，数据库单写；SDK线程/循环约束经适配试验确定；UI/策略/运维无写事实权 |
| 权限与事实分离 | 本机账户排他+boot/epoch+context；READY不自动ARMED，连接恢复不等于完整核对/新开仓授权 |
| 发送事务 | 必需计划、预占、意图/子单/可能发送标记先提交，Ack后临发复核；UNKNOWN不换ID盲目重报 |
| 保护独立 | 首笔部分成交即托管实际数量，保护不等待策略/GUI/通知，策略失权不删计划 |
| 受限IPC与计划 | 固定协议、schema和有限原语；未知字段拒绝；本地registry解析，不在校验时联网 |
| 退出唯一目标 | 同周期只有一份权威退出目标；所有出口共用潜在成交占用，不能各发全量 |
| 维护和回退 | 核心更新先禁新请求并建立事实屏障；代码回退不回退交易事实，STOP_COMMITTED不等于进程已退出 |

这些工程决定无需用户重复选择框架细节。需要业务确认的是具体触发/计数/参数/权限政策，见确认表。若实施试验发现平台能力不足，先更新受影响工程合同与矩阵，不在适配器里悄悄降低恢复/保护标准。

## 3. 环境兼容与账户条件矩阵

| 项目 | G0准备结论 | 定版/验证条件 |
| --- | --- | --- |
| Windows | 以Windows桌面/后台服务隔离为目标；首测候选Windows 11 x64 | 无用户登录、服务身份、ACL、不同会话、睡眠/恢复；其他系统不预称兼容 |
| Python/Qt | 常规CPython与PySide6 Widgets；具体版本不复用V7环境或DSV的3.14文件指纹 | W01在干净环境验证SDK wheel/ABI、Qt、服务、打包后锁精确版本与哈希 |
| SQLite | STRICT、JSON校验、FK、WAL/FULL及Backup能力为需求 | 本轮只验证本机空库结构；目标机器回读参数并做写失败/断电/备份恢复 |
| IPC | Windows命名管道、严格UTF8/JSON与本地schema registry | W03验证跨会话身份、拒绝远程、Qt互通、拆粘包/上限/超时/背压 |
| SDK/通道 | TqSdk生态先做能力试点；TqCtp需要相应外接条件；最终只有一条通道有权 | W06完成下表，不凭SDK类名/登录/字典稳定证明能力 |
| 秘密/身份 | 服务身份拥有秘密，配置只含引用；GUI临时录入经认证流程交服务保存 | DPAPI作用域、身份更换、重装/迁移、普通导出无凭据；生产环境另配 |
| 操作条件 | 测试账户、环境、通道、额度和允许动作尚未给新产品确定 | 真实在线模拟/真实资金分别落实，不继承参考软件或V7历史授权 |

准备矩阵不是安装或试点执行结果。G1可以先实现不持有交易连接的核心；在SDK适配或在线步骤开始前关闭其所需的环境/许可门禁。

## 4. W06通道完整性矩阵模板

TqAccount、TqCtp、原生CTP均标为“待证据”，没有从现有软件的运行推定新产品能力。候选比较在隔离环境/非重叠账户执行，不给同账户并发自动权。

| 能力 | TqAccount | TqCtp | 原生CTP | 必需证据及缺失后果 |
| --- | --- | --- | --- | --- |
| 显式环境/合法接入/线路权限 | 待证据 | 待证据 | 待证据 | 接入许可、实际SDK/账号类型与环境；不默认TqSim |
| 资金完整性与费用口径 | 待证据 | 待证据 | 待证据 | 范围、来源、时间、完成/不可得项；缺失不放资金闸门 |
| 持仓完整性与今昨/多空 | 待证据 | 待证据 | 待证据 | 完成屏障、方向/今昨范围及外部仓；不按净仓臆造归属 |
| 委托完整性与订单关联 | 待证据 | 待证据 | 待证据 | 跨重启身份、活动/终态、查询范围；UNKNOWN不能凭未查到释放 |
| 成交完整性与重复/乱序 | 待证据 | 待证据 | 待证据 | 稳定trade_key、部分成交/迟到、日切覆盖；不能重复记账 |
| 查询快照/增量衔接 | 待证据 | 待证据 | 待证据 | 来源代次、请求/完成、目标barrier；旧快照不覆盖新事实 |
| 行情粒度/首分钟/保护路径 | 待证据 | 待证据 | 待证据 | 可观察更新、日高低范围、路径连续性与缺口；不足则能力NOT_READY |
| 发送/撤单/部分成交 | 待证据 | 待证据 | 待证据 | 排队、实际调度、确认、成交分别取证；撤单竞态不超量 |
| 跨日/断线与安全重建 | 待证据 | 待证据 | 待证据 | 带仓/未知时能否延续管理，重建后完整核对；不支持则上线阻塞 |

技术负责人依据证据选择通道，用户提供目标环境与可取得权限，无需替实现团队证明API能力。原始字段到内部类型、身份/完成信号的映射在W06实现提交中逐项补齐。

## 5. G1任务输入与完成定义

| 任务 | 直接输入 | 交付及检查 |
| --- | --- | --- |
| W01 工程起步 | 本入口、兼容矩阵、构建白名单 | 独立环境/锁文件、无旧产品运行依赖、类型和纯逻辑测试入口 |
| W02 规格落代码 | 两个JSON Schema、SQL、B项与96行追踪 | 领域值类型/schema适配、规则/参数注册与批准解析，不自动APPROVED |
| W03 内核/IPC | 状态机、IPC、角色/context | 单owner、版本化命令、快照/增量、排他；杀GUI/策略不杀内核 |
| W04 账本/OMS | SQL、事务清单、发送/撤单状态 | pending预占、幂等、强杀点、迟到/乱序/UNKNOWN；不做SDK成功等于成交 |
| W05 保护 | Plan Schema、JSON黄金例、统一目标 | 首次部分成交、锁存、全部原语、开关/多空/奇数手反例；候选例保留开发标签 |
| W08 骨架 | epoch、checkpoint、屏障和切换状态 | 单代次、旧消息拒绝、提交前后恢复；完整实机热切换留到G5 |

先把状态reducer、表及事务、协议编解码、计划解释器写成独立模块；再以开发事件执行器验证纵向底座。开发执行器与测试数据不进入生产菜单或包。SDK真实在线闭环仍为G2，不能用开发事件替代。

## 6. G0结案范围与剩余门禁

| 项目 | 本轮结论 |
| --- | --- |
| 状态/模型/IPC/计划工程规格 | 已细化，跨文件字段、枚举、事务与引用进行静态复核 |
| 机器可读制品 | 两份Schema及SQL，附文档JSON例和规范化哈希向量；本轮执行静态校验 |
| 功能覆盖与实施归属 | 96行、W01–W14和G0–G6承接，无通过状态继承 |
| 业务规则/参数 | 已形成可集中答复的确认表；20项仍待用户确认，生产配置不可启用候选值 |
| 精确依赖/通道能力 | 已列验证矩阵和阻塞条件；未执行安装、SDK或在线验证，后续按W01/W06落实 |
| G1/G2及生产 | 尚未编码/连接/验收；没有创建E:\online-trader、安装服务或操作账户 |

因此本轮完成的是**G0规格与可行性准备的交付**，没有将业务待定或技术待验证伪装成上线通过。后续可直接按第5节进入通用工程实现，涉及未决业务/通道的动作继续受相应门禁约束。
