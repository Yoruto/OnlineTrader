### 控制协议

[开发与验收契约](../../control-contract.md)列出全部13种 `OperatorCommand` 的范围、接受条件、持久动作和成功后置条件：暂停、授权、清仓后停机、接管准备/确认、维护、手动开/平、三种撤单、核对请求及原退出恢复。

同 ID/hash 合并在途 Future 或返回已存回执；异 hash 明确冲突。首个业务事务原子记录命令和业务动作，只有相符 CommitAck 才返回持久回执；后续进度以单独事务增加 receipt_revision。收到请求、发送调用返回、成交和最终完成分开表示。重启查询原回执不会重发订单。

清仓完成必须有数量一致终态、无 UNKNOWN 和当前完整账户事实；空周期也不能跳过核对。接管确认逐一接受残余订单和未知 attempt，事实变化使旧清单失效。维护先 QUIESCING 并禁开，符合空仓/事实/占用/待提交屏障才 SAFE_TO_STOP；晚到事实或重启使原安全窗口持久失效。显式交接路径保留残余风险，不能冒充空账户。

新增风险的正向测试使用内部 DEVELOPMENT 政策和外部 QA RecordingPort，不提供公开登记接口。默认运行不安装交易适配器，无法通过开仓命令制造模拟资金、成交或 READY。未批准规则导致明确拒绝；请求核对只建立 REQUESTED 范围，不自证 COMPLETE。

### 已提交状态流

[状态流契约](../../stream-contract.md)说明 Snapshot/Delta/Gap、稳定订阅身份、有限保留重放和 Heartbeat/Ack。每次匹配 Ack 后冻结一份提交视图，服务逐份发布；不会把连续多次提交合并为最后状态，也不会把待提交权限或周期当作已持久事实。

快照校验账户/boot/connection、N/B边界、分块及整包hash、canonical投影和记录revision。源冲突、保留缺失或容量溢出显式 Gap，客户端保持 STALE 并重取完整快照。跨 boot 不复用旧状态；Gap后暂停心跳，完整快照/保留恢复完成后再用高水位确认。心跳活跃不证明行情新鲜、核对完成或交易就绪。

入站256帧/8MiB、每peer出站256帧/16MiB、提交视图和每流历史均有界；慢读者溢出只断开自身，不阻塞内核。服务最多16个peer、64个保留订阅。只读策略worker只能读取状态，不接收控制或下单权限。

最小窗口提供完整快照刷新与暂停入口；完整手动交易、接管和维护界面在 W10 继续。窗口关闭只关闭控制台。新长期只读客户端 `transport.subscription.LiveSubscription` 已完成实际管道验证，可供后续界面接入。
