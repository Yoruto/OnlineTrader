# G0 业务确认清单

日期：2026-11-09（Asia/Shanghai）。全部决定为 **PROPOSED / 待用户确认**。本清单将早期设计基线 `规则裁决表 v0.3`（索引见 [spec-source.json](../../spec-source.json)）转为可集中答复的问题，不修改其原件、不批准参数，也不重新询问已定的96项功能范围。

## 1. 确认方式与不会混在一起的权限

建议按下列六组一次答复“采用候选/按所列修改/待定”，再填写参数表。若修改了最终规则，必须登记具体B项、最终文字、受影响例及适用版本；“继续开发”只表示工程任务继续，不把待定规则自动改为APPROVED。业务规则确认也不自动授予账户登录、报撤单、真实资金、自动恢复或签名发布权限。

| 组 | 需要确认的核心问题 | 对应B项 |
| --- | --- | --- |
| Ⅰ 仓位与参数模式 | 不足一手是否一律不开；固定量超预算拒绝还是缩量；旧0值怎样迁移 | B03/B05/B16 |
| Ⅱ 入场与路径 | 80%还是90%；几何是否实时；延续开是否只豁免等待；同分钟/滞回/双价怎么判 | B02/B04/B08/B09/B10/B11/B20 |
| Ⅲ 保护与减仓 | 理论价冻结、80%锁存、半仓/二阶段/保本/移动、同事件优先级 | B14/B17/B18 |
| Ⅳ 时段与异常退出 | 合约日历/日切、收盘报价升级、断流/重复失败及应急范围 | B06/B07/B13/B14/B15 |
| Ⅴ 财务与停开 | 名义点数、真实人民币日亏、风险度、费用、报单、连续止损、滑点 | B12/B13/B16/B19 |
| Ⅵ 版本与操作责任 | 谁确认规则、哪些参数何时生效、暂停/接管/停内核、生产恢复责任 | B01/B07/B14/B17及本表第4节 |

候选不是建议投入资金的参数；它们是待定的软件行为规格。仅确认比例或数字不足以批准整条规则，比较符号、价格字段、适用范围和重置条件也必须明确。

## 5. 批准记录及开发分界

每项最终记录包含：B编号、来源、候选与最终差异、批准人/时间、适用规则集/组件/账户环境、参数与单位、正反例ID、迁移、生效/撤销条件、证据哈希。`rule_decisions`追加新revision；撤销是新记录，不覆盖已发生事实，也不撤销已有保护。

目前所有20项均PROPOSED。可先开发类型、表、状态机、队列、预占、幂等、计划解释器与候选事件测试；只有依赖B项均获批、相关参数完备且账户/环境操作范围明确后，才允许对应在线增仓。规则确认后的G1开发不需要再次确认已经定稿的功能范围。
