# 混合持仓归属与缺失原单回补

2026-11-11，OnlineTrader `0.1.0.dev24` 源码。本轮验证使用临时账本和离线柜台形状的输入，实际账户连接及线上报撤单均为零。

## 持仓调整

1. 在工作台打开“柜台持仓差异”，选中合约后点“核对并调整所选持仓”。人工工作台范围支持该操作。新的多日策略范围可在生成时指定 `--allow-external-allocation`，旧策略范围保持原授权。
2. 工作台比较柜台多空各自的今昨仓和原账本分桶。外部增量进入独立保护周期，保留同合约原周期、原计划和保护状态。新增周期使用柜台该方向的开仓参考价，原外部成交成本仍未知。
3. 外部减仓先按方向、今昨仓定位，再按该仓桶内已接受批次先入先出提出逐周期调减。确认框逐项列出受影响周期。反手在一个事务内调减原方向并纳管反向差额。调减是归属调整，原订单成交数量和半仓、保本的成交进度沿用原证据。
4. 确认后保存核对快照、方案和回执，暂停新增。原退出须经过当前源重新核对。柜台事实发生变化、存在活动委托、原单未决或归属证据不完整时保留屏障。已观察到成交但同方向今昨仓总量相等的换仓，仍需额外证据证明哪些原批次已经退出。

## 缺失原单

从柜台终态委托与逐笔成交证据整理 `NATIVE_TERMINAL_HISTORY/1` JSON，通过工作台“回补历史原单”核对账户和来源后提交。`workbench-status` 可查看当前账户、`configuration.gateway_identity`、`configuration.calendar_hash` 和已提交子单的 `native_order_id`。示例只展示字段，填入同一账户的实际柜台事实。

```json
{
  "schema_version": "NATIVE_TERMINAL_HISTORY/1",
  "account_key": "<当前账户键>",
  "gateway_identity": "<当前通道身份>",
  "calendar_hash": "<原交易日历哈希>",
  "statement_reference": "<对账单或柜台查询流水标识>",
  "orders": [
    {
      "order_id": "<原柜台单号>",
      "contract_id": "SHFE.bu2701",
      "direction": "SELL",
      "offset": "CLOSETODAY",
      "quantity": 2,
      "remaining": 1,
      "status": "FINISHED",
      "limit_price": "1048",
      "source_time_ns": "<原委托时间的Unix纳秒字符串>",
      "trades": [
        {
          "trade_id": "<原柜台成交号>",
          "quantity": 1,
          "price": "1048",
          "source_time_ns": "<原成交时间的Unix纳秒字符串>"
        }
      ]
    }
  ]
}
```

- 终态量按 `quantity - remaining` 计算，逐笔成交数量必须完全吻合。零成交终态使用空成交数组，柜台终态证据仍是必填项。
- 原执行内核核对订单身份、方向、开平、限价、手数、柜台交易日、已有逐笔事实及当前同步快照。保存回执表示证据已提交。后续沿原回报路径处理；相同历史证据重复提交不会重复成交。若原单重新出现并与历史证据冲突，继续阻挡恢复。
- 跨日后原退出沿原意图续报，使用当前日的今昨仓路由。恢复条件包括原单终态、逐笔明细、当前柜台仓位和新鲜报价。

固定版本 TqSdk 3.10.4 的 `get_order` 和 `get_trade` 读取当前同步集合。缺失时需从外部取得柜台证据并导入，当前未接直查历史接口，也未验证真实柜台对账单的导出格式。[固定 SDK 的查询实现](../output/online/sdk-venv/Lib/site-packages/tqsdk/api.py)
