# 交易运行时与执行合同

本文定义 Standalone Trading Runtime 如何将策略目标与用户指令转化为安全的柜台委托执行。

---

## 1. 核心执行不变量

1. **单 Owner / 单 Sender / 单写者**：整个 Runtime 生命周期内只有一个 `StandaloneDsvOwner` 持有 `DsvSdkAdapter` 发送权，并由单一线程写入当前 boot 的临时 `Journal`。
2. **`commit-before-send`**：任何开仓、平仓或撤单在调用 SDK 发送前，必须先在临时 `Journal` 完成落盘提交。
3. **`UNKNOWN` 保守占量**：若 SDK 调用抛出异常或结果未知（`SEND_POSSIBLE` / `UNKNOWN`），按最大可能剩余数量计入在途占量，在获得明确柜台回报或完整水位证据前禁止重复发单。
4. **撤单未终态不叠加发单**：同一合约同方向存在未终态冲突挂单时，必须先撤单并等待柜台返回明确终态释放可平仓位，再发新单。
5. **共享退出目标**：半仓止盈、固定止盈止损、移动止盈、收盘强平、手动平仓与收敛平仓共享同一净剩余退出目标；撤单请求未终态前不释放占量。

---

## 2. 全账户目标持仓收敛模型

Standalone 模式不区分“策略自有仓”和“外部/人工仓”，统一以 **账号实际持仓（Actual）** 对齐 **策略目标持仓（Desired / Target）**：

| 场景 | 当前合同要求 |
| --- | --- |
| **启动但未启动策略（`DISARMED`）** | 同步柜台事实、对配置合约执行 Plan B 推算目标、为有仓非配置合约设定目标 `0` 并在 Workbench 预览差异；**严禁自动发单或撤单**。 |
| **启动策略后（`ARMED`）** | 逐合约按 Actual 与 Target 执行收敛。先撤销所有非策略需要的活动挂单（含外部挂单、遗留挂单、非配置合约挂单），待撤单终态后收敛仓位。 |
| **非配置合约存在持仓** | 只要柜台返回存在持仓或活动挂单，按需动态订阅行情，目标恒为 `0`，`ARMED` 后以激进限价（保护限价/对手价滑点截断至涨跌停并对齐 `tick_size`）自动清仓。 |
| **实际持仓与目标方向相反** | 先撤销冲突挂单并激进限价平清反向持仓，确认归零后再按策略规则开立目标方向。 |
| **同向多余持仓** | 激进限价平掉超出目标的多余手数。 |
| **存在活动挂单与在途占量** | `target_execution.py` 统一核算 `Actual / Desired / Pending`（含 `SEND_POSSIBLE` / `UNKNOWN` / `CancelPending`）。当某侧收敛差额已归零但仍有在途收敛平仓单时，立即提交撤单（`CANCELLING_EXCESS_CLOSE`）。 |
| **某一合约无法交易** | 若某合约处于休市、集合竞价、停牌或涨跌停封板，单合约隔离排队等待下一个可交易时段，**不阻塞其他合约**。 |
| **`position_known=False`** | 单合约隔离为 `DEFERRED_FACTS_INCOMPLETE`，严禁以默认 0 持仓执行收敛或开仓。 |

## 3. Plan B 启动状态推算

由于每次 boot 使用全新的临时 `Journal`，启动时通过纯确定性函数结合**当前已确认配置**、**当前交易日完整柜台快照**（持仓、按交易日历窗口过滤的当日成交与当日分钟 K 线）以及可选的 `account-history.db` 历史统计，严格推算每个配置合约的初始目标与保护基线：
- **可证持仓**：当日开仓成交时间、方向与当日 K 线信号匹配策略规则，且开仓至今未触发止损/全平/强平，则保留策略应持目标并建立均价、`peak` 与 `half_stage` 基线。
- **不可证持仓**：无当日开仓成交记录、非信号点位、已过隔夜强平边界的昨仓、或已触发日停/止损的残余持仓，目标一律设为 `0`（`ARMED` 后自动清仓）。
- **日内目标归并**：同一开仓目标的多次撤改子单归并为 1 次策略目标；区分 `DAILY_TARGET_LIMIT` / `NET_LOSS_STOP`（禁开新仓，不强平合法在手仓位）与已实现止盈日停。
- **`DISARMED` 等待期间**：对 Plan B 推算持仓执行只读增量保护复核，零发单/撤单。

## 4. 统一市场交易权限与集合竞价门禁

Runtime 按合约独立计算市场阶段与权限（`market_phase`、`can_open`、`can_close`、`can_cancel`、`continuous_matching`、`status_source`）：
- **权限来源**：优先使用可选实时交易状态（`TqApi.get_trading_status`，无商业权限或超时自动无错降级）；否则以完整交易日历 + 可信时钟 + 当前时段有效行情作为 `INFERRED` 路径，并结合柜台拒单回报修正。非配置合约仅在内存中构建临时时段覆盖，不因存在报价时间即视为连续交易。
- **策略限制与减仓分离**：`participate_auction=False` 与 `no_open_after_open` 仅约束普通策略开仓；进入连续交易后（含开盘首分钟）立即允许收敛平仓、保护平仓与手动平仓等减仓操作。
- **集合竞价与非连续阶段**：开盘前、撮合期（开盘前最后 1 分钟）、盘中休市、停牌及收盘后禁止主动开/平仓（撮合期禁止撤单）；集合竞价申报期禁止主动开/平仓及撤单追价，仅在允许时撤销多余开仓单。市场暂不可交易时保留目标差额，恢复连续交易后自动继续。
- **拒单与失败分类**：`E_DSV_MARKET_PHASE` 不计入失败次数；`TRANSIENT` 拒单退避重试；结构性拒单基于原因与执行条件指纹判定是否可重算恢复，无交易权限等明确权限故障保持阻断报警。

---

## 5. 异常分级、授权代际与时钟约束

- **三档 Owner 异常分类**：`TRANSIENT_DISCONNECT`（瞬时断连，保留授权代际并重连）、`PERSISTENT_DISARM`（持久故障，解除开仓权限并置 `NEEDS_REVIEW` + `recovery_required`）、`FAIL_STOP`（存储或核心不变量破坏，安全停机）。`ControlServer` 遇未预期异常关闭客户端连接并 fail-closed。
- **授权代际（`authority_generation`）**：自动 `arm=True` 绑定当前代际；人工 `STOP`/`PAUSE` 或 `PERSISTENT_DISARM` 立即作废代际防复活，瞬时断线重连保留代际。
- **交易日与时钟**：`resolve_active_trading_day()` 仅在所有作用域日历 `complete=True` 且活跃合约交易日一致时推进，冲突则 fail-closed 报 `E_DSV_SCOPE`。Standalone 长时跨日运行超出原日历/窗口覆盖时，由 Owner 按当前合约行情与 SDK 交易日历自动续展下一交易日并同步更新连接作用域（保持 `resume_entries_on_day_change=False`，换日后维持 `DISARMED`；节假日前后未确认夜盘安排仍 fail-closed）。执行器使用应用内 NTP 校准的 UTC（单调时钟推进）；校时异常时暂停新开仓，同次启动内可凭原账户原账本 UTC 锚点（最长 15 分钟）继续维护既有持仓保护，超时或重启需重新授时。
- **合并交易所平仓路由**：`DCE`、`CZCE`、`CFFEX`、`GFEX` 平仓路由显式启用 `historical_first_on_combined=True`，`SHFE` / `INE` 按今昨仓严格分桶路由（不静默回退错误仓位类型）。
